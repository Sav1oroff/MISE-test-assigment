# Бронирование столика

Тестовое задание на Vue 3 / Nuxt 3 / TypeScript. Приложение имитирует бронирование столика в ресторане: пользователь заполняет данные, выбирает доступную дату и часовой слот, после чего видит экран подтверждения.

## Запуск локально

Требования: Node.js 18+ и npm.

```bash
npm install
npm run dev
```

После запуска приложение доступно по адресу `http://localhost:3000`.

Проверка production-сборки:

```bash
npm run build
npm run preview
```

## Структура

```text
app/
  pages/index.vue                              # состояние экранов и Transition
  components/BookingForm/BookingForm.vue       # поля, props/v-model и стили формы
  components/ConfirmationScreen/               # экран успешного бронирования
  composables/useBookingForm.ts                # состояние, слоты и валидация
  types/booking.ts                             # BookingFormData и BookingStatus
  assets/styles/main.css                       # общие токены и адаптивные стили
```

## Принятые решения

- Логику формы вынес в `useBookingForm`, чтобы страница отвечала за отображение, а вычисление дат, слотов и валидацию было сосредоточено в одном месте.
- Для валидации использован VeeValidate: ошибки доступны рядом с соответствующими полями и показываются при blur или попытке отправки.
- Состояние экрана описано типом `BookingStatus`: `idle`, `loading` и `success`; переходы между состояниями анимируются через встроенный Vue-компонент `<Transition>`.
- `BookingForm` получает настройки и ошибки через prop `bookingDate`, а изменяемые значения полей синхронизируются с родителем через именованные `v-model`.
- `ConfirmationScreen` получает готовую сводку через prop `booking` и сообщает о сбросе формы событием `reset`.
- Отправка симулируется задержкой `setTimeout` на 1,5 секунды, потому что по ТЗ backend и база данных не требуются.
- Доступные слоты строятся с шагом один час в диапазоне с 12:00 до 22:00; для текущей даты прошедшие слоты скрываются.

## Соответствие ТЗ

| Требование | Статус | Реализация |
| --- | --- | --- |
| Имя, телефон, дата, время, гости | Готово | Поля находятся в `BookingForm.vue` |
| Все поля обязательны | Готово | Схема VeeValidate |
| Имя: от 2 символов, буквы, пробелы, дефисы | Готово | `validateName` |
| Телефон `+7` или `8`, 10 цифр | Готово | `validatePhone` нормализует ввод через удаление разделителей |
| Дата от доступной даты до `+90` дней | Готово | `min`/`max` у date input и `validateDate` |
| Слоты 12:00-22:00 с шагом 1 час | Готово | `availableTimeSlots` |
| Ошибки при submit и blur | Готово | VeeValidate и `errors` рядом с полями |
| Имитация отправки 1,5 секунды | Готово | `setTimeout` в `submit` |
| Экран подтверждения с деталями | Готово | `ConfirmationScreen.vue` получает `booking` через props |
| Кнопка «Забронировать ещё» | Готово | `resetBooking` возвращает форму |
| `<Transition>` для смены экранов | Готово | `mode="out-in"` и ключи `form`, `loading`, `success` |
| Адаптивность 375px / 1280px | Готово | Вертикальная форма с ограниченной шириной и responsive CSS |
| Backend / база данных | Не требуется | Отправка намеренно симулируется |

## Ограничения

Данные не отправляются на сервер и не сохраняются после перезагрузки страницы. Доступность слотов рассчитывается только на клиенте и не учитывает реальные занятые столики.
